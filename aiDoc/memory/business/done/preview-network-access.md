# 预览局域网与固定公网入口

- 提出日期：2026-11-27
- 当前状态：`done`
- 需求类型：开发验收网络入口

## 用户意图

用户询问公网与局域网地址，并追问固定域名凭据问题的解决方式。

## 实施

- 原后端继续监听回环；增加独立的 LAN TCP 转发网关和 Cloudflare 隧道，兼容临时与命名两种模式。
- 网关按当前实例注册和进程身份转发，保留流式字节传输；停止/销毁同步停止入口，命名域名在刷新后保持不变。
- 当前 worktree 使用主机 192.168.0.152 的空闲 30410 端口，未改动旧 GVA 的 30400 和既有 Tunnel。
- status/check 输出网络地址和实际 build ID/首页大小与 SHA-256 探测结果；Cloudflare 注入统计脚本时额外核对原始首页及全部入口 JS/CSS 的 SHA-256。
- 用户重新授权后创建独立命名 Tunnel，成功绑定 `https://gva-dev1.zhiteng.win`；LAN 入口为 `http://192.168.0.152:30410`。运行凭据私有保存，未输出密码或 token。

## 凭据结论与限制

- Tunnel 创建成功，DNS 路由返回 403 / Authentication error；未将此错误直接断言为单一权限原因，账户/Zone 不匹配或旧证书也需核对。
- 正式域名需要有相应域名权限的账户重新授权，或限定 zhiteng.win 的 DNS Edit API Token；运行 token 不等于 DNS 管理凭据。
- 2026-11-27 用户自行重新授权，账户不变、证书绑定 Zone 更新，DNS CNAME 创建成功，原凭据问题已解决。未使用的测试命名 Tunnel 已删除。
- 固定域名无预设过期时间，在实例和隧道运行期间可访问；stop/destroy 停止访问但保留 DNS/Tunnel。临时 Quick Tunnel 会变更地址且不支持 SSE，当前已切换命名隧道。
- 默认 Python 探测 UA 被边缘规则拒绝；改用明确的应用标识后通过，不修改安全设置。公网统计脚本注入导致 HTML 字节不同，因此采用原始首页登记哈希、构建标识与入口资源逐一核验。没有声称完成异机 LAN 或人工浏览器验收。
